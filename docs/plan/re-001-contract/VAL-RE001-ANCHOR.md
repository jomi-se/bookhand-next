# VAL-RE001-ANCHOR: Reflow preserves the same semantic passage

Surface: browser.
Needs: Bookhand `1743074` with official Foliate `78914aef4466eb960965702401634c2cb348e9b1`, the exact candidate build, and independent fixtures with delayed, broken, and deliberately hanging media/font cases.
Behavior: Viewport resize, repeated portrait-landscape-portrait cycles, font size/line height/measure changes, custom CSS apply/reset, late media/font completion, broken media, and media/font hangs that do not trigger navigation recovery settle within `READER_NAVIGATION_DEADLINE_MS` (5,000 ms) after the final trigger. Success means the same normalized quote-plus-CFI passage is visible and controls respond. If a case triggers the existing navigation deadline, it follows `VAL-RE001-LIFECYCLE` and `VAL-RE001-FRAME`: the old passage remains visible while a speculative same-origin replacement gets up to two sequential `BOOK_OPEN_DEADLINE_MS` operations, for a 25,000 ms total bound from the original trigger. Recovery success establishes a new frame lifetime at the preserved location; recovery failure shows `.reader-section-error[role="alert"]` with enabled `Try again` while the last safe passage remains visible.
Evidence: Per-transition before/after quote, CFI, section and viewport geometry on exact baseline/candidate; measured trigger-to-settle/recovery time and event timeline; ordinary 5,000 ms anchor result or explicit 25,000 ms recovery-lifetime result; control-response/recovery-state assertions; screenshots/traces for drift or fallback.
Fail: Raw pixel/page number alone is used as the oracle, ordinary reflow exceeds 5,000 ms, recovery exceeds 25,000 ms, the old safe passage blanks before replacement, or drift is hidden by navigating back after measurement.
Oracle: Semantic quote plus exact CFI, not visual page number.
